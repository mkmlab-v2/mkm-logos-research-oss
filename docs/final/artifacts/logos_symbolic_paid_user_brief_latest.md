## S2W 기사 기반 체화 팩 (엔디소프트 실행안)

### 0) 핵심 전환 (모델 중심 -> 구조 중심)
- `핵심 메시지`: LLM 성능 경쟁보다 `온톨로지 + 추론 경로 + 검증 루프`를 제품화해야 B2B 신뢰를 얻는다.
- `우리 적용`: 답변 품질 개선 문구보다 먼저 `왜 이 결론인지`를 보여주는 설명 레이어를 기본 기능으로 둔다.

### 1) 우선순위 문제 정의 (전사 구축 금지)
- `원칙`: 모든 데이터를 온톨로지화하지 않는다. 매출/이탈/리스크 같은 단일 과제부터 시작한다.
- `우리 1순위 과제`: `사용자 질문 -> 근거 추적 가능한 답변`으로 전환해 유료 전환 신뢰도를 높인다.
- `DoD`: 샘플 질의 20건에서 근거 경로 누락률 `0%`, 근거 충돌률 `<=5%`.

### 2) 최소 온톨로지 스코프 (MVP)
- `Entity`: `질문`, `도메인 태그`, `근거 소스`, `주장`, `리스크 고지`, `행동 권고`.
- `Relation`: `supports`, `contradicts`, `derived_from`, `gated_by`, `requires_human_approval`.
- `출력 계약`: 최종 답변은 항상 `결론 1줄 + 근거 3개 + 반증/한계 1개 + 행동 가이드 1개`를 포함한다.

### 3) XAI 기본 규격 (설명 가능한 답변)
- `Trace ID`: 질의마다 `decision_trace_id`를 부여해 입력-근거-출력 연결을 보존한다.
- `근거 표준`: 근거는 `source_type`, `source_id`, `claim_type(FACT/HYPO)`, `confidence`를 포함한다.
- `금지`: 근거 없는 확정 표현(`항상`, `무조건`, `보장`)과 신학/투자 단정 문구.

### 4) 하네스 엔지니어링 체크리스트 (운영 핵심)
- `입력 게이트`: 스키마 검증 실패 시 답변 생성 대신 `HOLD` 반환.
- `추론 게이트`: 상충 근거가 임계치 초과 시 강등(`WATCH`) 및 수동 검토 큐로 이동.
- `출력 게이트`: 대외 카피는 `research_only` 경계를 자동 삽입하고 금지어 스캔을 통과해야 발행.

### 5) 8주 실행 로드맵 (가볍게 시작)
- `1-2주`: 최소 온톨로지 정의 + 샘플 50문항 라벨링 + 출력 계약 고정.
- `3-4주`: 질의->근거 그래프->결론 파이프라인 연결, trace 저장.
- `5-6주`: 반증/충돌 처리 게이트 + 수동 검토 큐 운영.
- `7-8주`: 고객사 파일럿 1건, 전/후 KPI 비교 리포트 산출.

### 6) KPI (레퍼런스 확보용)
- `설명 가능률`: 답변 중 근거 3개 이상 포함 비율 `>=95%`
- `근거 정합률`: 근거-결론 충돌 없는 비율 `>=90%`
- `검토 시간`: 담당자 검토 시간 `30%` 이상 단축
- `유료 전환`: 질문 서비스 결제 전환율 `+10%` 이상 개선(동일 기간 비교)

### 7) 영업/제안서 문장 (바로 사용)
- `우리는 모델 성능을 과장하지 않고, 의사결정의 근거 경로를 추적 가능한 구조로 제공해 실무 신뢰를 확보합니다.`
- `온톨로지는 전사 대공사가 아니라, 고객의 핵심 문제 1개를 빠르게 해결하는 최소 구조부터 적용합니다.`
- `현재는 research_only 경계를 유지하며, 운영 반영은 별도 리스크 게이트 승인 항목만 단계적으로 수행합니다.`

## 1+3 작업 실행 명세 (임계치 + 2단 게이트)

### 목적
- 외부 시장/IR 논의와 분리하여, 운영 체계는 `팩트 기반 경보 체계`로 고정한다.
- `7일/14일 임계치`와 `warning/critical` 이원 게이트를 표준화한다.

### 범위 (이번 단계)
- `1`: 경보 임계치 재튜닝(7d/14d)
- `3`: 게이트 확장
  - `warning` 단계: 관측 강화 + 자동 완화 조치
  - `critical` 단계: fail-close + 강제 HOLD/수동 승인

### 입력 계약 (요약)
- `window_7d_metrics`: 7일 집계 지표
- `window_14d_metrics`: 14일 집계 지표
- `policy_thresholds`: 임계치 정책(JSON)
- `latest_gate_state`: 직전 게이트 상태

### 출력 계약 (요약)
- `gate_level`: `ok | warning | critical`
- `reason_codes`: 판정 근거 코드 배열
- `actions`: 자동 실행된 완화/강등 조치
- `next_review_utc`: 다음 재검토 시각

### 판정표 (고정)
- `critical`: 14일 기준 핵심 조건 위반 또는 단일 치명 조건 위반
- `warning`: 7일 기준 악화 신호 누적(치명 조건 미해당)
- `ok`: 경보 조건 미충족

### 게이트 동작
- `warning`:
  - 자동 집행 강화 금지
  - 관측 주기 단축
  - 운영 알림 발행
- `critical`:
  - 즉시 `HOLD` 강등
  - 수동 승인 없이는 승격 금지
  - 감사 로그/증적 번들 필수 생성

### DoD (완료 정의)
- 임계치 정책 파일이 7d/14d 분리로 고정됨
- `warning/critical` 경로에 대한 테스트 케이스 통과
- 일일 체인에서 판정/조치/로그가 아티팩트로 남음
