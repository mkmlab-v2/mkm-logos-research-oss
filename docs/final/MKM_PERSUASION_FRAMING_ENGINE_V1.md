# MKM Persuasion Framing Engine v1

작성일: 2026-05-09  
목적: 마케팅, 제안서, 피치, Q&A에서 심리학적 영감을 엔지니어링 규율(Fact-Lock)로 변환해 일관되게 적용한다.

---

## 1) 핵심 3원칙

### 1.1 손실 선점 (Risk-First)

- 장점 나열 전에 상대가 실제로 겪는 통제 실패 리스크를 먼저 정의한다.
- 리스크는 정량 또는 재현 가능한 언어로 표현한다(예: 지연 꼬리, 무결성 이탈, 운영 장애 전이).
- 금지: 공포 과장, 경쟁사 비방, 검증 불가 단정.

### 1.2 프레임 전환 (Rule-of-Game Shift)

- 비교 기준을 "모델 점수 경쟁"에서 "운영 무결성/게이트 통제 능력"으로 이동한다.
- 핵심 질문은 "무엇을 책임지고 어떤 조건에서 안전하게 운영하나?"로 고정한다.
- 결과적으로 상대가 평가할 축을 운영 책임성과 검증 가능성으로 통일한다.

### 1.3 차가운 증거 닫기 (Evidence Close)

- 감정적 주의 환기 뒤에는 반드시 아티팩트와 수치로 닫는다.
- 형용사 대신 근거 경로, 게이트 상태, 제한사항을 제시한다.
- 수치 상수는 고정 문구로 박지 않고 `*_latest.json` 등 최신 산출물을 참조한다.

---

## 2) 이해관계자별 손실 매핑

- CTO/엔지니어: 지연 꼬리(P99), 제어 경합, 장애 전이 리스크.
- CFO/구매: BOM 증대, 운영비 상승, 재작업/유지보수 비용 누수.
- 사업부/운영: 오작동 신뢰 하락, CS/리콜 비용, 출시 지연 리스크.

규칙: 상대 유형에 맞는 손실 훅 1개만 선점하고, 즉시 통제 전략과 검증 경로를 붙인다.

---

## 3) 대외 커뮤니케이션 번역 규칙

- 내부 메타포(예: 뇌 레이어 설명)는 외부 본문에 그대로 노출하지 않는다.
- 대외 문장은 항상 아래 3요소를 포함한다.
  - 위험 정의(현재 통제 공백)
  - 통제 구조(게이트/운영 정책)
  - 검증 경로(아티팩트/수치 + 제한사항)

표준 응답 순서: `결론 -> 근거(아티팩트) -> 제한사항`.

---

## 4) Adjective-to-Evidence 규칙 (형용사 세척)

### 4.1 금지/주의 표현 예시

- 혁신적, 완벽한, 최고의, 압도적, 100%, 무조건, 절대.

### 4.2 치환 규칙

- "혁신적이다" -> "어떤 게이트/검증을 통과했는지"로 치환.
- "최고다" -> "비교 조건과 측정값"으로 치환.
- "완벽하다" -> "적용 범위 + 한계 + 다음 검증 단계"로 치환.
- "100%" -> "관측 기간/표본/조건을 포함한 수치"로 치환.

### 4.3 셀프 체크 질문

- 이 문장에 형용사만 있고 경로/수치가 없는가?
- 근거 파일을 상대가 직접 확인 가능한가?
- 제한사항(로컬 기준선, 보드 실측 전환 등)을 명시했는가?

---

## 5) 아티팩트 하이퍼링크 표준

- 수치 문장 아래에 근거 경로를 붙인다.
  - 예: `근거: docs/final/artifacts/<name>_latest.json`
- 가능하면 JSON/리포트 1개 + 검증 스크립트 1개를 같이 제시한다.
  - 예: `검증: scripts/verify_p0_constitution_gate_paths.ps1`
