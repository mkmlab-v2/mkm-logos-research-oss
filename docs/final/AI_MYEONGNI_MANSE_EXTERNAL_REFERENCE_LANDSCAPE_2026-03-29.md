# 외부 AI·명리·만세력(사주) 활용 참조 랜드스케이프

**작성일**: 2026-03-29  
**목적**: NotebookLM B(연구·통찰) 보강용 — **다른 제품·서비스가 명리·만세력·사주 계열을 어떻게 AI와 결합하는지** 요약. MKM 구현과 혼동 금지: 본 문서는 **참고·영감**이며, 본선 팩트·OOF·트리거는 `CONSTITUTION_INFERENCE_IMPLEMENTATION_FACTS.md` 및 A 노트 SSOT를 따름.

## 1. 공통 패턴 (아키텍처 관점)

| 패턴 | 설명 | MKM에서의 위치 |
|------|------|----------------|
| **규칙엔진 + LLM** | 만세력·대운·십성 등은 전통 규칙/표로 계산 → 결과를 LLM에 넣어 해설·대화 | 헌법상 **근원(Logos)과 확장(레짐·매매) 분리** — verse 파이프라인에 regime 혼입 금지 |
| **순수 LLM** | 프롬프트만으로 사주 해석 (정확도·재현성 리스크) | 연구·브레인스토밍용으로만 참고 |
| **RAG + 챗봇** | 문서(고전, 매뉴얼)를 인덱싱해 질의응답 | NotebookLM·로컬 RAG와 유사한 **근거 붙이기** 목적 |
| **앱 내 “AI 상담”** | 계산은 네이티브, 상담은 클라우드 LLM | 제품 카피·UX 참고 |

## 2. 해외·영어권 (웹·문서 기준)

- **Master Tsai / AI Bazi 계열**: 사주 팔자 입력 → 차트·기둥 산출 후 AI 해석을 강조하는 랜딩·도구가 다수 존재. 일반적으로 **입력 검증 → 전통 계산 레이어 → 자연어 설명** 구조.
- **“BaZi GPT” / DocsBot·프롬프트 템플릿**: 커뮤니티·SaaS에서 “팔자 데이터를 구조화해 GPT에 넣는 프롬프트” 패턴이 공유됨 — **재현 가능한 계산은 코드·표로**, LLM은 **해설만** 담당하는 식이 권장되는 논의가 많음.
- **Cantian AI, Compass AI Bazi 등**: 브랜드별로 “AI-powered” 문구와 함께 Bazi 리포트·챗 형태 제공 — 세부 알고리즘은 비공개인 경우가 대부분.

**참고 시 주의**: 상업 페이지는 **마케팅 과장** 가능. 기술 검증은 공개 논문·오픈소스·자체 재현이 우선.

---

## 3. 국내·한국어권 (앱·서비스 설명 기준)

- **만세력·명리 앱 “AI” 표기**: 스토어·랜딩에서 **대운·신살·합충형파** 등 자동 산출 + **챗봇/요약/운세 문구 생성**을 “AI”로 묶어 표기하는 사례가 흔함.
- **천을귀인, SAVIS 등**: 제품 설명상 LLM·추천·상담 연동을 언급하는 경우 있음 — **정확한 모델명·데이터 경로는 외부에서 확정 불가**이므로 “가능한 UX 패턴” 정도로만 참고.
- **교육용 만세력·절기**: “AI 연결”보다 **달력·절입 시각 DB + 규칙**이 핵심인 서비스도 많음 — MKM **만세력 E2E**와 비교 시 **어디까지가 팩트 락인지** 구분.

## 4. MKM 노트북 A/B와의 정렬

| 구분 | 권장 |
|------|------|
| **A (Fact-Lock)** | 제품 경로·스키마·체크리스트·구현 팩트만. 외부 “AI 상담” 카피는 **넣지 않거나** 한 줄 참고로 제한. |
| **B (Creative-Lock)** | 본 문서처럼 **타사 UX·패턴·영감** 정리. **본선 자동 합선·OOF·트리거 규칙은 스키마·헌법 문서가 우선.** |
| **B 코호트(원전·Proxy)** | 한의 원전 말뭉치와 **역할 분리** — `KOREAN_MEDICAL_CANON_INGEST_HANDOFF_2026-03-28.md` 준수. |
