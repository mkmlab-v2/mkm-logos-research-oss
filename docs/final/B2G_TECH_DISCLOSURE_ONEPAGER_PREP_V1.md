## 2. 1페이지 본문 목차(한 장 안에 넣을 블록)

아래 순서는 **명세 초안용 습관적 구획**이지, KIPO 양식 번호와 1:1이 아니다. 제출 전 **공식 서식**으로 맞춘다.

1. **발명의 명칭(가칭)**  
   - 예: “근거 연동·출력 보류·사용자 확정을 포함한 문서 초안 생성 장치 및 방법” 등 — **마케팅 용어·‘만능’·‘전 세계’ 금지**(B2G Fact-Lock과 동일 톤).

2. **기술분야**  
   - 예: 자연어 처리, 정보 검색, 워크플로 제어(해당 시만).

3. **배경 기술(최소)**  
   - 일반 LLM만으로는 고위험 문서에서 **추적·거부·사람 승인** 요구를 만족하기 어렵다는 **한두 문장** 수준. 외부 논문 인용은 부록 `B2G_CONTROL_INTEGRITY_PROPOSAL_ANNEX_V1.md` **각주 [1][2]만** 대응(제안서와 동일 정책).

4. **해결하려는 과제**  
   - “공식 근거와 연결되지 않은 생성”, “필수 항목 누락”, “승인 없는 다음 단계 진행” 등 **측정 가능한 운영 과제**로 쓴다.

5. **과제의 해결 수단(핵심 구성요소)** — 레포 Fact-Lock 앵커(예시, 과제 범위에 맞게 선택·삭제)

   - **정책자금·공모 과제 ①(초안)** 관점: 공고·서식 수집 → 인덱싱 → **RAG** → 항목별 **슬롯 템플릿** → **무결성 게이트(HOLD·재질의·사용자 확정)** → PDF/hwp — 상세 서술은 사업계획 초안 `docs/final/artifacts/ai_opendata_challenge_2026_327_business_plan_overview_v1.md` **개발계획 절**과 **동일 선상**으로만 쓰고, **미구현을 구현한 것처럼 쓰지 않는다**.
   - **실행 거버넌스(ECC·HOLD 예시)**가 출원 가치 논의에 포함될 때만: `docs/final/CONSTITUTION_INFERENCE_IMPLEMENTATION_FACTS.md` 에 정리된 **`scripts/athena_run_v1.py`**·HOLD 시 exit code·감사 산출 개요를 **요약 한 문단**으로 인용(경로·스크립트명은 **내부 별첨**으로 두거나 마스킹).

6. **실시예(2~3개)**  
   - 실시예 1: 정책자금 신청서 **특정 슬롯**(예: 사업 개요·시장) + 근거 청크 연결.  
   - 실시예 2: HOLD로 **다음 단계 차단** + 사용자 확인 후 진행.  
   - 실시예 3(선택): 부록 1.1과 정합되는 **광의 CDSS 확장은 개념 한 문장**만 — **임상·SaMD 완료 주장 금지**.

7. **도면(선택)**  
   - 한 장 블록도: “수집 → RAG → 게이트 → 출력 → 감사 로그”.

8. **효과(과장 금지)**  
   - “환각 0”이 아니라 **감사 가능·재현 절차·게이트 통과 조건** 등 **검증 가능 표현**만.
